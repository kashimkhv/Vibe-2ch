# AGENTS.md

Правила для агентов, которые правят этот репозиторий.

## Версии и релизы

`3.3.1` — текущая версия (тег `v3.3.1`, `versionCode = 8`). История пакета:
в `3.0.0` он был `dev.dvach.client`; с `3.0.1` — `io.github.kashimkhv.vibe2ch`,
привязанный к namespace, который контролирует автор. `3.0.0` не обновляется
поверх: её APK отозван. Любая следующая правка, которая попадёт в релиз, обязана
поднять версию — «хороший тон» здесь это SemVer:

- **patch** `3.0.x` — исправления без новых возможностей;
- **minor** `3.x.0` — новые возможности с обратной совместимостью;
- **major** `x.0.0` — несовместимые изменения: смена `applicationId`, формата
  локальных данных без миграции, ломающее поведение API приложения.

Правила:

1. `versionName` и `versionCode` меняются в `app/build.gradle.kts` **в том же
   коммите, что и сама правка**, а не отдельным «version bump».
2. `versionCode` — целое, только растёт. Опубликованный код никогда не
   переиспользуется, даже если релиз отозван: Android не установит APK с
   меньшим или равным кодом поверх существующего.
3. Релиз — это тег `vX.Y.Z` и GitHub Release с `Vibe-2ch-X.Y.Z.apk`; имя файла
   и тег совпадают с `versionName`.
4. Перед тегом: `:app:testDebugUnitTest`, `:app:assembleRelease`,
   `apksigner verify --print-certs`, установка и smoke-тест на эмуляторе.
5. Debug-сборку версия не поднимает: `versionNameSuffix = "-debug"` сам
   отличает её, а `versionCode` у неё общий с release.
6. В release notes публикуются SHA-256 APK и отпечаток сертификата.
7. Ключ подписи и `keystore.properties` не коммитятся и не теряются: без них
   обновления поверх опубликованной версии невозможны.
